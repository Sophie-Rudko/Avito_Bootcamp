# Детекция парсеров Авито по событиям cookie

Решение тестового задания: для каждой `cookie_id` из `test.csv` модель выдаёт `score` от 0 до 1, где выше значит вероятнее бот. Метрика — Precision при Recall ≥ 0.70.

## Файлы

| Файл | Что это |
|---|---|
| `solution.ipynb` | Весь код с комментариями и выводами: проверка данных, признаки, валидация, бейзлайны, абляции, финальная модель, сабмит |
| `submission.csv` | Предсказания для `data/test.csv` |
| `metric.py` | Официальная метрика из задания (без изменений) |
| `requirements.txt` | Версии библиотек |

## Как запустить

```bash
# Python 3.12
pip install -r requirements.txt
# положить рядом с ноутбуком: data/train.csv, data/test.csv, data/events.csv.gz, sample_submission.csv, metric.py
jupyter nbconvert --to notebook --execute solution.ipynb --output solution_executed.ipynb
```

Полный прогон занимает около 6 минут на одном ядре. Сиды зафиксированы, LightGBM работает в одном потоке с `deterministic=True`. Два независимых прогона дали одинаковый файл, md5 `submission.csv` печатается в последней ячейке.

## Описание подхода

**Обработка событий.** Оставила только события внутри окна `[window_start_ts, window_end_ts)`. 12% событий лежат после конца окна, у ботов таких 42%, и там же все показы капчи, поэтому их использование было бы утечкой. Удалила 4863 полных дубля. Отсортировала события по времени. Привела `platform` из 11 написаний к трём значениям. Время перевожу в секунды через `total_seconds()`: в pandas 3 даты хранятся в микросекундах, и `astype('int64')` даёт неверный результат.

**Признаки (90 поведенческих + 6 по истории):**
- интервалы между событиями внутри сессий: квантили, разброс, доли по корзинам, доля почти равных соседних интервалов, самая «машинная» сессия;
- сессии и темп: число и длина сессий, событий в минуту, ночная активность;
- состав событий: доли типов, фото, избранное и контакты на один просмотр;
- поиск: глубина и порядок пагинации;
- объявления: число объявлений, категорий и городов, повторы, переключения городов;
- курсор: наличие на web, разброс и повторяемость координат;
- клиент: возраст куки, доли платформ;
- общие объявления с другими куками того же дня;
- репутация объявлений: доля ботов среди посетителей объявления за прошлые дни. Для куки из дня d используются только метки за дни < d; в валидации — только метки обучающих дней, для test — все дни train.

Сырые `user_agent`, запросы и категории в модель не идут: доля ботов по ним плохо переносится между неделями. Флаги из User-Agent дали прирост в пределах шума, непостоянный по фолдам, и в итог не вошли.

**Модель.** LightGBM (400 деревьев, 31 лист, min_child_samples=50), среднее по 5 сидам, обучение на всём train.

**Ограничения.** Репутация объявлений помогает, пока сервисы обходят тот же пул объявлений. Новый сервис будет пойман только поведенческой частью (около 0.75–0.80 на валидации). Разброс метрики между фолдами ±0.03–0.04.

**Библиотеки:** pandas, numpy, scipy, scikit-learn, LightGBM. LLM и внешние API не используются.
